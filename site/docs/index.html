Get started

Install Git and Node.js 22.13 or newer. Clone the tool and install its dependencies. Use the path to your own project clone when starting the dashboard.

git clone https://github.com/TOberpaul/ai-performance.git
cd ai-performance
npm ci
npm start -- "<path-to-your-project-clone>"

Open the printed loopback URL. The current setup uses the tool's Git repository. To update it, pull the latest changes, run npm ci again, and update the installed hook scripts when their templates change.

How collection starts

Enable the hooks you want in your own clone. Keep collection hook configuration local if each contributor should opt in independently. Starting the dashboard opens the project database. The hooks record new activity while you work in the corresponding tool.

Codex

  1. Copy telemetry/.codex/hooks/ from the tool into .codex/hooks/ in your project. Merge the entries from telemetry/.codex/hooks.json into your project's .codex/hooks.json.
  2. Review and trust the hooks in Codex under Settings → Hooks or with /hooks in the CLI. Use your own local hook configuration when deciding whether to collect usage.
  3. Work in Codex. The usage hook records available token counts per model attempt. The history hook saves available start context, timing and quota measurements at turn completion, interruption and session end.

Kiro

  1. Copy telemetry/.kiro/hooks/ into .kiro/hooks/ and telemetry/.codex/hooks/performance-store.cjs into .codex/hooks/ in your project.
  2. Start a Kiro session in the clone. The AgentStop hook records the completed run as Kiro. To associate runs with a known ticket at capture time, set AI_PERFORMANCE_TICKET_ID in the environment that starts Kiro.
  3. Supply measured per-run credits through the record command when you have a source for them. Account and pool balances have separate records.

Connect a run to a ticket

Give each ticket a stable ID, a name and an epic. A ticket can contain runs from several tools. Codex links a recorded attempt via the session ID and turn ID in the ticket's subtasks. For Kiro, use a ticket ID during capture or copy the key shown under Unassigned runs and link it later.

npm run record -- ticket ticket.json "<path-to-your-project-clone>"

The ticket view adds up recorded work time and shows tokens and credits in their original units. An unknown measurement appears as missing. Codex quota windows and Kiro account or pool observations describe usage at different scopes, so the dashboard shows them separately.

See the record command reference for JSON examples.

What stays in your clone

Each local clone has its own .codex/performance.sqlite. Add the following rule to the target repository's .gitignore or your clone's .git/info/exclude before collection begins.

/.codex/performance.sqlite*
/.codex/context-packages.json
/.codex/context-usage.jsonl
/.codex/context-history/

The database contains ticket metadata, tool and model names where available, run references, timings, and usage and quota measurements. The supplied hooks omit prompt text, replies and tool output. GitHub Pages publishes this guide. Your dashboard is served on your computer.

Everyone using a separate clone gets a separate database. People with access to the same checkout can access its database.

Migrate and back up your data

On first open, the tool copies legacy ticket data, usage logs and saved measurements into SQLite. To capture measurements still available in Codex history, run the import from the tool directory before deleting old chats.

npm run import-history -- "<path-to-your-project-clone>"

Saved measurements remain available after their source chat is removed. Back up .codex/performance.sqlite while collection and the dashboard are stopped. If the source chat and its measurements are already gone, recovery requires a backup.
